# Rehla skill workflow

1. Start with rehla-development; read AGENTS.md and relevant Cursor rules.
2. Apply rehla-karpathy-guidelines when framing ambiguous work, deciding scope, coding, reviewing, or refactoring: surface material assumptions, avoid speculative complexity, keep diffs surgical, and define verifiable goals.
3. For new/changed behavior use rehla-specification and record unresolved decisions.
4. For multi-step changes use rehla-planning then rehla-executing-plans, inline only.
5. Use rehla-tdd for behavior and rehla-systematic-debugging for failures.
6. Review with rehla-code-review and verify with rehla-verification.
7. Use rehla-branch-finish for branch disposition; rehla-release only for authorized release.
8. Use rehla-skill-authoring for skill changes and test one skill at a time.
9. Engineering skills are narrow guides and do not replace the workflow.

Static artifact validation is distinct from model behavior evaluation. Karpathy guidelines do not override approved requirements, security/privacy, authorization, or TDD.
